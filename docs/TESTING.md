# Testing

Run from the repository root. Keep outputs outside Git. The toolchain is pinned to Rust 1.98.0; chain tests use Foundry/Anvil 1.8.4 and solc 0.8.31. Test scripts use Python 3.9+ (the release dependency check needs 3.11+).

Targeted route-comparison and observation-age regressions:

```sh
cargo test --locked --test simulation --test diagnostics
cargo test --locked --lib routes::registry
```

These checks exercise the real gas/simulation admission with deterministic RPC boundaries and loopback HTTP probes. They cover later-provider selection, gas-adjusted ranking, source failure/timeout, expired results, zero-net eligibility and stale readiness. They do not require a public RPC or a signer key.

## Layout

- `tests/*.rs`: Cargo integration tests; small unit tests stay beside their implementation.
- `tests/unit/`: larger internal synchronization and load harnesses.
- `tests/solidity/`: executor contract tests; `tests/testnet/`: optional deployable test stack.
- `tests/python/`: offline orchestration and script checks.
- `tests/runners/`: local, fork and testnet entry points.
- `tests/fixtures/`: pinned inputs, generated bytecode and protocol test vectors. Third-party license notices belong to these inputs.

## CI and container checks

`scripts/ci-checks.sh` is shared by generic CI and release automation. It validates the Git SDK pin and fixture hashes, then runs Python tests, Rust tests and the configured Clippy checks. It requires Python 3.11+, Rust 1.98.0 and Clippy; it never invokes a formatter.

After building an image, run `python3 tests/runners/test-container.py IMAGE`. This starts a disposable keyless container with networking disabled and checks read-only/non-root operation, health during RPC failure, log redaction, temporary key-file copy permissions and graceful shutdown. It always removes its container and temporary fixture. Docker is required; these checks are not substituted by YAML validation.

## Local checks

```sh
cargo test --locked
python3 -m unittest discover -s tests/python
ANVIL=/path/to/anvil bash tests/runners/test-local-bot.sh all
ANVIL=/path/to/anvil bash tests/runners/test-local-rpc-e2e.sh full
```

The SDK is fetched from the Git revision in `Cargo.toml` and `Cargo.lock`; no sibling SDK repository is needed. Add `--offline` to Cargo when dependencies are cached. The local runners use isolated loopback Anvil, development keys and pinned bytecode. They check full/partial/bad-debt liquidation, maturity, oracle and financial guards, lender matching, withdrawal, RPC/send failures, in-process reorg handling and SIGTERM. Test results do not imply restart recovery of pending transactions.

Factory discovery has a separate fresh-Anvil check (no private lending sources required):

```sh
ANVIL=/path/to/anvil cargo test --locked \
  --test factory_discovery_local -- --ignored
```

It starts an empty-catalog live bot with a shared 15 RPC/s budget and 300-ms blocks, creates a lending pool through its trusted factory, opens an unhealthy position, and confirms a finalized atomic liquidation without configuring that pool on the executor. It also checks later creations, duplicate discovery, token review/retry, restart census, untrusted-factory rejection and `config init` without pool/factory flags, plus strict `--pool` filtering and rejection of mixed pool/factory flags. Solidity tests cover lookalike pools, changed or reverting factories, pool versions and constructor bounds. Unit tests also cover reorg rejection, bounded pages, duplicate updates and keeping existing workers alive.

## Load

```sh
BARTERLEND_LOAD_OUTPUT=/external/load bash tests/runners/test-local-load.sh all
```

Profiles: **1200** (4 pools × 2 markets × 150 debts) and **4000** (8 × 2 × 250), blocks every 300 ms, one mutation per pool per two blocks, one shared 15 RPC/s budget. Default responses take 100 ms, with every tenth request taking 500 ms. Each profile includes cold census, faults, restart and a steady phase. Each test is limited to 20 minutes. The runner fingerprints the SDK resolved by `cargo metadata`, so reports identify the Git source actually used. The synthetic HTTP harness checks synchronization and scheduling; it does not execute EVM swaps. Its RSS includes the harness and report buffers.

For actual EVM load, use the private fixture wrapper below and run `tests/runners/test-local-multipool.sh /external/fresh-output` with `BARTERLEND_BULK_POOLS=4` or `8`. It creates 1200/4000 genuine debts, selects 32 for liquidation across both markets, measures all bot RPC items with a proxy, and reconciles debt, profit, nonce and MON balances. Anvil uses 300-ms blocks and one slot per epoch for its simulated finality. Without `BARTERLEND_BULK_POOLS`, the runner checks two pools and multiple debts per market.

The separate retention check runs the actual keyless CLI for 18 real minutes, with new borrower IDs, full debt closures and oracle changes. It measures bot RSS and file descriptors separately from Anvil. Export a seed during an EVM run with `BARTERLEND_EXPORT_SEED=/external/seed`, then run:

```sh
python3 scripts/bounded-test.py python3 tests/runners/test-local-retention.py \
  --seed /external/seed --output /external/fresh-retention \
  --bot /path/to/barterlend-liquidator --anvil /path/to/anvil --cast /path/to/cast
```

This needs `ps` and `lsof`. It does not measure Tokio task counts or prove absence of slow leaks beyond the bounded run.

## Contract integration sources

Private lending source copies are not distributed. Rust and seeded Anvil checks work with the pinned bytecode already included. To compile the Solidity integration suites or regenerate fixtures, provide the matching private fixture bundle externally. It contains `protocol-v5/{src,test,foundry.toml}` and `upstream-compat/`; hashes are checked against the provenance manifests.

```sh
export BARTERLEND_PROTOCOL_FIXTURES=/external/private-fixtures
python3 scripts/with-protocol-fixtures.py -- env \
  FORGE=/path/to/forge SOLC=/path/to/solc \
  bash tests/runners/test-solidity.sh --no-match-contract ExecutorSeedGenerator
```

The wrapper temporarily mounts ignored source directories and removes its mounts on exit. It refuses to replace existing directories. Source checks explicitly report when private inputs are unavailable; generated artifact hashes remain mandatory. Public builds and images never need these sources. Differential math fuzzing uses the same external bundle and the bot's pinned input manifest:

```sh
python3 scripts/with-protocol-fixtures.py -- env \
  FORGE=/path/to/forge SOLC=/path/to/solc \
  python3 tests/runners/test-math-differential.py --output-dir /external/fresh-math --runs 4096
```

## Forks

`test-monad-fork.py` uses a pinned historical block for V4. It needs historical RPC state; all transactions stay local. `test-kyber-fork.py` fetches a current block and records its hash before starting a local Monad fork. It checks actual Kyber API calldata and real token/DEX execution inside the executor, with a synthetic lending callback. Provide an external JSON containing `rpc_url`, `input`, `output`, `amount` (decimal raw units), `kyber_router`, `v3_router`, `v3_factory`. No private key is accepted.

```sh
python3 scripts/bounded-test.py python3 tests/runners/test-kyber-fork.py \
  --config /external/kyber-fork.json --output /external/fresh-fork-results \
  --anvil /path/to/anvil --cast /path/to/cast
```

Build the Solidity artifacts first with the private fixture wrapper. Public RPC is restricted to read methods. A local fork does not prove mainnet inclusion, live quote freshness or coverage of other pairs and sizes.

## Testnet

Use dedicated funded wallets and an explicit spending budget. First build bytecode with `build-testnet-artifacts.py` under the private fixture wrapper, then run the local `test-upstream-smoke.py --mode plain --execute-local` rehearsal. Both scripts expose their required paths through `--help`.

`run-testnet.py` uses explicit phases and external evidence/secret directories. Its provisioning tool retains signed setup transactions for accounting; this is separate from the stateless bot. The bot's finalized console events plus independent on-chain reads form test evidence. Never publish sources through verification services. Kyber is tested on a local mainnet fork; Monad testnet is not assumed to support its API or liquidity.

`testnet-scenarios.py --execute --common-args /external/args.json --scenario maturity` adds a maturity-only case after the primary HF test. Continue with `partial` and `multipool` to reuse the same test AMM and exercise two pools/two markets. The common-args JSON is the argument list for `run-testnet.py`, including external paths and the explicit test budget. Its owner key must remain outside Git.

After extra scenarios, use `--scenario cleanup` on this helper: it closes extra borrower positions and claims matured loans **before** invoking the primary cleanup and removing AMM liquidity. If maturity is still in the future, it reports pending and keeps liquidity. `--wait-market` in common arguments enables a bounded wait. Reuse the original evidence directory; never delete signed setup journals to retry a failed phase.

Local, fork, testnet and container results are separate. A clean release needs a published SDK pin, a container build/run and a real rollout check. No public network test starts automatically from these local commands.
